# MachineGuard

## Caderno de Testes – SYSTEM #001

**Título:** Validação do Baseline e dos Parâmetros de Detecção da Condição da Máquina

---

## Objetivo

Validar o comportamento do `task_system` utilizando o motor em condição real de operação.

O teste tem como objetivo:

- validar o processo de warm-up;
- validar a construção do baseline saudável;
- avaliar a média e o desvio padrão das features;
- avaliar o comportamento dos Z-scores;
- verificar o comportamento do threshold;
- avaliar a decisão baseada em 2 de 3 features;
- verificar a persistência de 5 avaliações consecutivas;
- observar o comportamento do estado `HEALTHY`;
- verificar se pequenas variações da operação normal não provocam `ALARM`;
- identificar parâmetros que necessitem de calibração.

O objetivo desta etapa **não é validar uma falha específica**, mas avaliar o comportamento estatístico do sistema durante a operação normal do motor e determinar se os parâmetros atuais são adequados para a detecção.

# Teste 1 — Warm-up e construção do baseline

### Objetivo

Validar a coleta das 600 avaliações necessárias para a construção do baseline da condição saudável do motor.

### Condição

Motor operando em condição considerada saudável e estável.

### Procedimento

- Fixar o acelerômetro na posição definida para o teste.
- Ligar o motor.
- Aguardar a estabilização da rotação.
- Iniciar/reiniciar o firmware para iniciar o warm-up.
- Aguardar as 600 avaliações.
- Registrar a quantidade de avaliações válidas de 1×RPM.
- Registrar o baseline calculado pelo `task_system`.

### Resultados

| Característica | Resultado |
|---|---:|
| Warm-up total | 600 avaliações |
| Avaliações realizadas | 600 |
| Avaliações 1×RPM válidas | 600 |
| RMS mean | 0.034232 g |
| RMS stddev | 0.000983 g |
| Kurtosis mean | 1.912225 |
| Kurtosis stddev | 0.199190 |
| 1×RPM mean | 0.088991 g |
| 1×RPM stddev | 0.002640 g |

Os logs registram explicitamente `warm-up: 600/600 | 1xRPM valid: 600` e `baseline validity: RMS=1 | Kurtosis=1 | 1xRPM=1 (600/100) | overall=1`. :contentReference[oaicite:1]{index=1}

### Resultado esperado

- 600 avaliações concluídas.
- O motor permanece em condição saudável e estável durante o warm-up.
- RMS e Kurtosis apresentam distribuição estável.
- Existe quantidade suficiente de picos 1×RPM válidos.

- O sistema entra em `HEALTHY`.

O baseline das três features foi considerado válido e o sistema entrou em `HEALTHY`. :contentReference[oaicite:2]{index=2}

# Teste 6 — Persistência da condição normal

### Objetivo

Verificar o comportamento da contagem de avaliações normais e confirmar que o sistema não oscila de estado durante a condição saudável.

### Procedimento

- Manter o motor em condição saudável.
- Observar o estado do sistema durante várias avaliações.
- Verificar que somente avaliações relevantes ao estado atual são contabilizadas.

### Resultados

| Avaliação | Resultado | Estado | Contador |
|---:|---|---|---:|
| 1 | NORMAL | ALARM | 1/5 |
| 2 | NORMAL | ALARM | 2/5 |
| 3 | NORMAL | ALARM | 3/5 |
| 4 | NORMAL | ALARM | 4/5 |
| 5 | NORMAL | ALARM → HEALTHY | 5/5 |

O log registra explicitamente a sequência `normal evaluation: 1/5` até `5/5`, seguida de `state changed: HEALTHY`. :contentReference[oaicite:8]{index=8}

### Resultado esperado

- O sistema permanece em `HEALTHY`.
- Avaliações normais não geram contagem desnecessária para transição.
- Uma avaliação `ABNORMAL` inicia a sequência de entrada em `ALARM`.
- Uma avaliação `NORMAL` interrompe uma sequência anormal.

### Resultado obtido

- [x] Conforme esperado
- [ ] Divergente

Observações:

O comportamento de recuperação foi observado diretamente: cinco avaliações normais consecutivas foram necessárias para retornar de `ALARM` para `HEALTHY`.

O código também confirma que uma avaliação anormal interrompe a sequência normal durante `ALARM`, enquanto uma avaliação normal interrompe a sequência anormal durante `HEALTHY`. :contentReference[oaicite:9]{index=9}

# Teste 7 — Avaliação dos parâmetros estatísticos

### Objetivo

Avaliar se os parâmetros atuais utilizados pelo detector são adequados para a operação real do motor.

### Parâmetros analisados

| Parâmetro | Valor atual | Avaliação |
|---|---:|---|
| Z-score threshold | 3.0 | Adequado preliminarmente |
| Features necessárias | 2/3 | Adequado preliminarmente |
| Avaliações consecutivas para ALARM | 5 | Adequado preliminarmente |
| Avaliações consecutivas para HEALTHY | 5 | Adequado preliminarmente |
| Mínimo 1×RPM válido | 100 | Conservador; validado neste teste |

### Análise

#### Z-score threshold

Avaliar:

- frequência de valores acima do threshold;
- ocorrência de falsos positivos;
- distância das condições normais ao threshold.

Resultado:

O threshold de 3.0 não provocou uma transição indevida durante a operação normal observada.

Entretanto, como os Z-scores individuais não são registrados no log, não é possível determinar a margem estatística real existente entre os valores normais e o threshold.

**Avaliação: adequado preliminarmente.**

---

#### Decisão 2/3

Avaliar:

- frequência de avaliações com 0/3;
- frequência de avaliações com 1/3;
- frequência de avaliações com 2/3;
- frequência de avaliações com 3/3.

Resultado:

A lógica implementada exige pelo menos 2 das 3 features acima do threshold para classificar uma avaliação como `ABNORMAL`. :contentReference[oaicite:10]{index=10}

O log demonstra que o sistema conseguiu distinguir a condição normal da condição anormal, mas não registra a quantidade de features anormais por avaliação.

**Avaliação: adequada preliminarmente, porém necessita de instrumentação para validação estatística detalhada.**

---

#### Persistência de 5 avaliações

Avaliar:

- duração temporal da persistência;
- frequência de sequências anormais;
- ocorrência de oscilações de estado.

Resultado:

O parâmetro apresentou comportamento coerente.

Foram observadas cinco avaliações anormais consecutivas, levando o sistema de `HEALTHY` para `ALARM`. :contentReference[oaicite:11]{index=11}

Posteriormente, foram observadas cinco avaliações normais consecutivas, levando o sistema novamente para `HEALTHY`. :contentReference[oaicite:12]{index=12}

**Avaliação: validado funcionalmente.**

---

#### Mínimo de 100 avaliações 1×RPM

Avaliar:

- quantidade real de `peak_valid` durante o warm-up;
- percentual de avaliações válidas;
- estabilidade da componente 1×RPM.

Resultado:

Foram obtidas **600 avaliações 1×RPM válidas em 600 avaliações de warm-up**, correspondendo a 100% de validade.

O requisito era de apenas 100 avaliações válidas. Portanto:

**600 / 100 = 6,0× o requisito mínimo.**

**Avaliação: parâmetro validado para esta condição experimental.**

---

### Resultado esperado

Os parâmetros atuais devem permitir:

- estabilidade em `HEALTHY` durante operação normal;
- baixa ocorrência de avaliações `ABNORMAL` isoladas;
- ausência de transições indevidas para `ALARM`;
- baseline suficientemente representativo da condição saudável.

### Resultado obtido

- [x] Parâmetros adequados
- [ ] Necessária calibração
- [ ] Necessária alteração arquitetural

Observações:

Os parâmetros apresentaram comportamento funcional adequado no teste realizado.

Entretanto, o `SYSTEM_ZSCORE_THRESHOLD = 3.0` e a votação 2/3 ainda devem ser avaliados com uma massa maior de dados, principalmente porque os Z-scores individuais não estão sendo registrados.

### Comentários finais

O teste demonstrou que o `task_system` é capaz de construir um baseline válido a partir de 600 avaliações do motor em operação. Todas as 600 avaliações apresentaram uma componente 1×RPM válida, enquanto RMS, Kurtosis e amplitude 1×RPM apresentaram baseline estatisticamente válido. :contentReference[oaicite:13]{index=13}

O baseline obtido foi:

- RMS: **0.034232 ± 0.000983 g**
- Kurtosis: **1.912225 ± 0.199190**
- Amplitude 1×RPM: **0.088991 ± 0.002640 g**. :contentReference[oaicite:14]{index=14}

A componente espectral também apresentou comportamento consistente, com a rotação permanecendo aproximadamente em **1745 RPM** durante a condição normal. :contentReference[oaicite:15]{index=15}

O mecanismo de persistência também foi validado experimentalmente. Uma sequência de cinco avaliações anormais levou o sistema para `ALARM`, enquanto cinco avaliações normais consecutivas posteriormente levaram o sistema novamente para `HEALTHY`. :contentReference[oaicite:16]{index=16} :contentReference[oaicite:17]{index=17}

Portanto, o comportamento funcional do sistema foi considerado **aprovado para esta condição experimental**.

## Observações para calibração futura

Os parâmetros atuais não apresentam necessidade imediata de alteração com base neste teste.

Entretanto, recomenda-se melhorar a instrumentação do `task_system` antes de uma calibração definitiva, registrando:

- Z-score individual de RMS;
- Z-score individual de Kurtosis;
- Z-score individual de 1×RPM;
- quantidade de features classificadas como anormais;
- classificação final `NORMAL` / `ABNORMAL`;
- valor do contador de persistência;
- estado atual.

Isso permitirá determinar quantitativamente a margem existente entre a condição saudável e o threshold de `Z = 3.0`.

Além disso, o parâmetro `SYSTEM_MIN_BIN_VALID_EVALUATIONS = 100` mostrou-se bastante conservador neste teste, pois foram obtidas 600 avaliações válidas. Não há, entretanto, justificativa suficiente neste único teste para reduzir o valor.

Nenhum parâmetro deve ser alterado definitivamente apenas com base nesta execução. As alterações devem ser justificadas pelos dados experimentais coletados em diferentes condições de operação.
